### 优化点

#### 数据库

因为比赛的竞赛等级对应的获奖等级所得的分，在所有比赛分类中都是一样的，所以得分情况不用保存在数据库中，在前后端硬编码实现，得分详情：

| 参与院级以上比赛： 2分/项（负责人）                          |      |      |      |
| ------------------------------------------------------------ | ---- | ---- | ---- |
| 院级获奖每项增加： 一等奖2分；其它等级奖 1.5分；优秀奖 1分   |      |      |      |
| 自治区级获奖每项增加：二等奖 5分；三等奖4分； 优秀奖3分      |      |      |      |
|                                                              |      |      |      |
| 个人业务比赛获：国家级一等奖15分、二等奖 12分、三等奖 10分、优秀奖8分； |      |      |      |
| 自治区级（行业性全国）一等奖7分（12.6分）                    |      |      |      |

删除比赛分类表、activity_type表、activity_rank_grade_score表，这些都不需要作为表，直接硬编码在前后端；修改competition_record表为teacher_competition_record，新增一个type_name，其值为教师比赛，因为比赛分类表、activity_type表、activity_rank_grade_score表不需要，所以需要存ID的位置，改为存储前端传来的值，删除category_id、activity_type_id ;将教师比赛类的比赛审核记录单独作为一张表；

#### 前后端

在我的记录界面，提供一个选择比赛分类的标签，不同标签下的列表查询与提交比赛记录有不同的模块，访问不同的比赛审核记录表；例如前端在我的记录界面选择了教师比赛分类的标签，查询teacher_competition_record表获得数据，在添加记录时，需要按照该表填写用户需要填写的信息
